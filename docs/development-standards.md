# Auto-Guardable Development Standards

## Purpose

This document defines engineering expectations for maintainable and responsible development.

## Code Quality

Prefer:

- readability over cleverness
- explicit behavior
- simple solutions
- composition over unnecessary inheritance
- clear interfaces

## Testing Philosophy

Testing provides:

- confidence
- documentation
- safe refactoring

Tests should be added when they improve confidence in behavior or prevent regressions.

## Security Expectations

Every feature should consider:

- authentication
- authorization
- data exposure
- secrets handling
- safe defaults

## AI-Assisted Development

AI tools may accelerate development, but engineering responsibility remains with contributors.

AI-generated work must:

- be reviewed
- be understood
- follow architecture decisions
- meet quality expectations
- include appropriate verification

AI is a development tool, not a replacement for engineering judgment.

## Decision Making

Important architectural decisions should be documented rather than remaining as undocumented assumptions.

The repository should preserve the reasoning behind significant choices.
